# PPC (Product Problem Clear) 프로토타입

생산관리자가 부품 재고와 발주를 한 화면에서 확인하고, 부품 공급에 차질이 생기면 대체 업체와 그 결과를 바로 비교해 결정하는 웹 프로그램입니다. 팀 ICBM · 설계 기준은 [docs/DESIGN.md](docs/DESIGN.md)(설계서 v0.2)입니다.

## 실행

**가장 쉬운 방법**: `ppc` 폴더의 **`start-ppc.bat`**(Windows)을 더블클릭합니다. 처음이면 패키지를 설치하고, 개발 서버를 띄운 뒤 브라우저를 자동으로 엽니다. Node.js가 없으면 설치할지 물어봅니다. macOS는 `start-ppc.command`를 씁니다.

직접 실행하려면 Node.js 22.12 이상이 필요합니다. (없으면 `winget install OpenJS.NodeJS.LTS`)

```bash
cd ppc
npm install
npm run dev        # http://localhost:5173
```

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm test` | 단위 테스트 (설계서 §9 기대값, 저장 흐름, 대시보드 값) |
| `npm run build` | 타입 검사 + 배포용 빌드 (`dist/`) |
| `npm run data` | `data/ppc_data.xlsx` + `data/ppc_extra.xlsx` → `src/data/reference.json`, `employees.json` 다시 만들기 (Excel을 고친 뒤 실행) |
| `npm run qr` | 발표용 QR 무늬 → `src/data/qr.json` 다시 만들기. 배포 주소가 바뀌면 `npm run qr -- https://새주소/` |

## 저장 방식: 공유 DB / 로컬 데모

상단 바의 배지로 지금 어느 쪽인지 알 수 있습니다.

- **공유 DB** — `.env.local`에 Supabase 값이 있을 때. 같은 주소를 연 사람은 모두 같은 데이터를 봅니다(캠프 완성 기준).
- **로컬 데모** — 값이 없을 때. 이 브라우저(localStorage)에만 저장하고, 처음 열면 시연 데이터가 자동으로 들어갑니다. 다른 사람과 공유되지 않습니다.

### Supabase 연결 (설계서 부록 C-1)

1. Supabase 프로젝트를 만들고 SQL Editor에서 [supabase/schema.sql](supabase/schema.sql)을 실행합니다.
2. `.env.example`을 `.env.local`로 복사하고 두 값을 채웁니다.
   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
   ```
   secret key(`sb_secret_…`)는 절대 넣지 않습니다. `.env.local`은 커밋하지 않습니다.
3. 개발 서버를 다시 시작하고, 화면의 **[시연 데이터 넣기]**(또는 [데이터 초기화])를 한 번 누릅니다.

### Vercel 배포 (설계서 부록 C-3)

- Root Directory: **`ppc`** (앱이 저장소의 하위 폴더에 있습니다)
- Framework Preset: Vite · Build Command `npm run build` · Output Directory `dist`
- Environment Variables에 위 두 값을 같은 이름으로 넣습니다. 값을 바꾸면 Redeploy해야 반영됩니다.
- `vercel.json`이 있어 `/disruptions/D-001` 같은 주소를 새로고침해도 404가 나지 않습니다.

### 3D 차량 뷰어

저장소 루트 `car-manager/`의 3D 스튜디오(three.js)를 대시보드의 '부품 재고' 영역으로 옮겼습니다. BOM 7개 부품(엔진·변속기·브레이크·서스펜션·조향·차체·배터리)이 핫스팟으로 붙어 있고, 누르면 그 부품으로 줌인하면서 재고·입고 현황 카드가 뜹니다. 부품 상태(차질 빨강 / 대응 중 파랑 / 주의 주황)는 핫스팟의 점과 해당 부품 메쉬의 색으로 표시됩니다. WebGL을 쓸 수 없는 브라우저에서는 도면 이미지로 대신합니다.

## 설계서와 다른 점 · 덧붙인 점

- **로컬 데모 모드** (설계서에 없음): Supabase 값이 없어도 앱을 띄워 볼 수 있게 넣었습니다. 공유가 필요한 시연에서는 반드시 Supabase를 연결하세요.
- **3D 차량 뷰어** (설계서에 없음): `car-manager`의 화면을 반영해 달라는 요청으로 추가했습니다. 이 때문에 `three`(r128 고정, car-manager와 같은 버전)가 의존성에 들어갑니다.
- **조사 처리**: 문구 T3의 `{부품}을`과 취소 경고의 `{부품}이`는 받침에 따라 을/를, 이/가를 고릅니다(예: "배터리를"). 엔진·조향처럼 받침이 있는 부품은 설계서 예문과 똑같이 나옵니다.
- **기간 내 미완료 주문**: 고객 안내 문구(T5)는 `lateDays > 0`인 주문만 만들고, 예측 기간 안에 끝나지 않는 주문은 안내 문구 대신 경고 한 줄을 보여 줍니다.
- `applyOriginalPoAction`은 어느 차질의 지연 발주인지 알아야 해서 `disruptionId` 인자를 하나 더 받습니다.

## v0.2 이후 추가된 규칙 (설계서에 없는 것)

- **기준일은 항상 오늘**: DB의 `base_date`가 아니라 화면을 연 기기의 오늘 날짜를 씁니다. [데이터 초기화]는 시연 데이터의 날짜(발주일·도착 예정일·납기)를 오늘에 맞춰 옮깁니다. 리허설에서 날짜를 고정하려면 환경 변수 `VITE_BASE_DATE=2026-10-05`를 줍니다.
- **사원번호 권한**: 발주, 대체 발주 확정, 발주 취소, 납기 추가·취소, 데이터 초기화는 Excel '발주권한자' 시트(발주 권한 Y)에 있는 사원번호를 입력해야 합니다. 권한은 하나이며 나누지 않습니다. 테스트용 사원번호 `0000`은 Excel과 상관없이 항상 통과합니다(`src/lib/employees.ts`).
  - 화면에서 하는 확인이라 실수 방지용입니다. 명단이 앱에 들어 있고 DB는 열려 있으므로 보안 장치는 아닙니다.
  - 사원번호 입력칸은 비밀번호처럼 가려집니다(●●●●). 발표 화면에 번호가 비치지 않게 하려는 것이고, 번호가 맞으면 아래에 이름·부서만 나옵니다. 이력의 '입력자' 칸에는 `이름(사원번호)`가 그대로 남습니다.
- **QR 접속 페이지**: QR 무늬는 `qrcode-generator`(개발용 의존성)로 미리 만들어 `src/data/qr.json`에 넣어 둡니다. 화면은 그 파일만 읽으므로 배포되는 앱에는 라이브러리가 들어가지 않습니다. 오류 복원 수준 Q, 29×29칸, 둘레 여백 4칸, 순수 검정/흰색입니다.
- **발주대기 / 발주 취소**: 발주한 당일의 일반 발주는 이력에서 '발주대기'로 보이고 그날까지만 취소할 수 있습니다. (DB에는 '입고대기'로 저장하고 화면에서만 구분합니다.)
- **업체별 발주 한도**: 한 업체에 일반 발주로 넣을 수 있는 수량은 일주일 동안 50개입니다. 발주일로부터 7일이 지나면 풀립니다. 시연 초기 발주와 대체(긴급) 발주는 한도에 넣지 않습니다. 기준값은 `src/lib/constants.ts`에 있습니다.
- **부품 주의사항**: Excel '주의사항' 시트를 읽어 3D 뷰어의 부품 상세에서 [주의사항] 버튼으로 보여 줍니다.
- **출차 일정 · 수리 차량 페이지**, **납기 추가 · 납기 취소**.

### 추가 Excel (`data/ppc_extra.xlsx`)

`자동차부품_생산관리_가상데이터_업체별단가추가` 파일의 사본입니다. 이 파일의 공급업체 시트는 납기 준수율이 전부 93%인 예전 값이라 쓰지 않고, **새로 생긴 시트만** 읽습니다. 업체·부품 기본 정보는 계속 `data/ppc_data.xlsx`가 기준입니다. Excel을 고친 뒤에는 `npm run data`를 실행합니다.

| 시트 | 쓰는 곳 |
|---|---|
| 업체별_자재단가 | **발주 금액** = 업체의 자재 단가(원/kg) × 부품 1개당 소재 필요량(kg) × 수량. 발주 화면, 입고 예정 표, 이력에 표시하고 합계를 냅니다. 취소한 발주는 0원. 금액은 DB에 저장하지 않고 Excel 단가로 계산합니다(단가를 고치면 과거 발주 금액도 바뀝니다). 예산 한도는 없습니다. |
| 지연시간 | **수량에 따른 납품 지연**. 도착 예정일 = 기준일 + 업체 기본 납기 + 지연. 단계는 1개 / 10개 / 50개 이상(엔진 3일·2주·2개월 등). 나눠 시켜도 피할 수 없게, 그 업체에 최근 일주일 동안 넣은 같은 부품 수량을 합쳐서 단계를 정합니다. 대체(긴급) 발주와 시연 초기 발주에는 적용하지 않습니다. |
| 차량색상 | **색상별 차체**. 차체는 색상마다 따로 있는 부품(`P012-C01` … `P012-C05`)이고 따로 발주·입고합니다. 차 한 대에 다섯 색 가운데 하나가 들어가며, 그 차의 색이 됩니다. 차량 고유번호는 `C01-YRI0V072`처럼 색상 코드로 시작합니다. 투입할 때 재고가 가장 많은 색의 차체부터 씁니다(자동차 주문은 색을 지정하지 않습니다). |
| 발주권한자 | 사원번호 권한 확인 |
| 주의사항 | 부품 주의사항 |
